# Радио как функция ассистента

На главной и изображениях нет отдельного радиоплеера или карточек станций. Функция доступна через текстовую/голосовую команду ассистенту:

- «включи Радио Дача», «поставь Авторадио», «включи радио [название]»;
- «включи радио» — последняя успешная станция, иначе RADIO_DEFAULT_STATION;
- «выключи радио», «поставь радио на паузу», «продолжи радио»;
- «другое радио», «предыдущая станция», «что играет»;
- «громче», «тише», «громкость 40 процентов».

Обращение необязательно. Эти команды обрабатываются локально и не расходуют LLM-квоту. Фраза «включи свет на кухне» не перехватывается поиском радиостанций. Неоднозначное название требует уточнения.

В `CAPSULE_MODE=simulation` поток виртуальный, звука нет. В `host` нужен установленный mpv: звук играет на машине с сервером. Чтобы это был динамик Капсулы, процесс должен работать на совместимой колонке либо требуется отдельно настроенный аудиоклиент. Одна настройка IP не переносит звук на колонку.

```dotenv
CAPSULE_MODE=host
RADIO_MAX_VOLUME=75
RADIO_DEFAULT_STATION=Радио Дача
RADIO_RESUME_AFTER_REBOOT=false
```

Поиск — Radio Browser и локальный кэш. Свои разрешённые HTTP(S) потоки можно сохранить через API `POST /api/v1/radio/stations` с полями id/name/urls; несколько urls задают альтернативы одной станции. API защищён тем же токеном владельца. Есть pause/resume, watchdog, retry с backoff, URL failover и сохранение последней успешной станции. При отказе Gemini поток продолжает играть.

Во время обработки одной голосовой команды поток приглушается; AEC на физической колонке не подтверждён. Скрипт `scripts/soak.py --station ID --hours 24` проводит реальные сутки и отказывается подменять их симуляцией. Быстрый тест виртуальных суток проверяет только логику, не аппаратную стабильность.
