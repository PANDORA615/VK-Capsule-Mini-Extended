# Приёмка на физической колонке

Статус всех пунктов: `hardware_verification_required`. Работайте только со своим устройством. Этот список не является командой прошить колонку.

1. Зафиксировать ревизию платы, маркировку SoC, RAM/NAND и безопасный уровень UART. USB-дескрипторы читать `capsulectl discover`; без предположений о VID/PID. UART — только RX/GND, после измерения уровня: `capsulectl uart-log PORT OUTPUT`. Открытие USB-UART может менять линии управления; физически не подключать TX/DTR/RTS. Скорость 115200 — настраиваемый пример, не гарантия.
2. Сохранить boot log, device-tree compatible и `/proc/mtd` через уже разрешённый интерфейс. `capsulectl identify compatible.txt`, `capsulectl firmware partitions proc-mtd.txt`. Это не сканер чужой сети и не автоматическая SSH-авторизация.
3. Получить полную резервную копию методом именно этой платы. Встроенный `backup create` только копирует ранее экспортированный обычный файл; не читает NAND и не решает OOB/ECC. SHA-256 подтверждает целостность копии, но не восстановимость. Дампы/калибровки/ключи не помещать в Git.
4. Проверить recovery отдельно, до изменения системных разделов. `capsulectl recovery plan --profile amlogic_a113x` всегда dry run. `recovery validate` возвращает отказ (exit 2), пока нет реализации проверенного метода. eFuse/OTP и уникальные заводские калибровки не менять.
5. По источнику для совпавшей платы исследовать временную загрузку; отдельно подтвердить root, запуск своего ядра, звук и запуск после полного отключения питания. Не переносить A113X образ на RK3308B.
6. На рабочем Linux проверить `aplay -l`, `arecord -l`, доступные ALSA mixer controls, драйвер усилителя и микрофонов. Установить безопасную громкость; записать/воспроизвести звук 60 минут. Не включать 100% для первоначального теста.
7. Проверить верхние/передние индикаторы, кнопки, аппаратный и программный mute. Убрать конкурирующие процессы дисплея. Задокументировать подтверждение агента и реально наблюдаемый результат отдельно.
8. Настроить выбранный способ активации в выбранном агенте. Проверить на разных голосах, паузах, расстояниях и при домашнем шуме; замерить ложные активации/пропуски. Не объявлять правило над распознанным текстом обученной акустической моделью.
9. Проверить потерю Wi-Fi на две минуты, HTTP 429/401 и недоступность обоих AI. Меню и свет должны оставаться доступны.
10. Выполнить длительную проверку голосовых запросов с логом, измерить CPU/RAM/температуру и задержку ответа. Отдельно проверить перезапуск сервиса и отключение питания с сохранением пользовательских настроек.

Шаблон отчёта: дата, владелец/разрешение, ревизия, фотографии без серийников, версия ПО/ядра, команды и условия, фактические измерения, `verified / simulated / unverified / blocked`. Изменение статуса допускается только с приложенным доказательством.
