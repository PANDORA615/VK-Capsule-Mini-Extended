# VK Capsule Mini Extended — техническое задание v3.0

**Проект:** VK Capsule Mini Extended / Marusya AI Replacement  
**Назначение:** превращение собственной VK Капсулы Мини в независимую голосовую колонку с сохранением привычной фразы «Маруся», голосовым интернет-радио и автоматическим переключением между Gemini 3.8 Live и Gemini 3.5 Flash-Lite.  
**Исполнитель:** OpenAI Codex  
**Референс:** https://github.com/Marker284/yandex-station-extended  
**Статус:** техническое задание, а не подтверждение работающего способа перепрошивки.

## 0. Главное задание для Codex

Ты — senior embedded Linux engineer, firmware researcher, Linux audio/DSP engineer, Python backend developer и QA lead. Создай настоящий открытый репозиторий, который последовательно решает задачи исследования собственной VK Капсулы Мини, безопасного запуска независимой ОС на подтверждённых аппаратных ревизиях и реализации голосового ассистента. **Главная пользовательская ценность — мама должна продолжать включать любую доступную радиостанцию привычной командой «Маруся, включи [название]» и слушать радио целый день.**

В качестве основного режима разговоров реализуй Gemini Live API (`gemini-3.8-live`), а при исчерпании квоты или технической недоступности — автоматический fallback на текстовую `gemini-3.5-flash-lite` с отдельным STT/TTS. Команды управления радио, громкостью, остановкой воспроизведения и восстановлением последней станции должны выполняться **без обращения к LLM**, когда они распознаются локально. Радиопоток никогда не отправлять в Gemini.

Разрабатывай реальный код, проверки и документацию; не выдавай заглушки за готовые функции. Если у Codex нет доступа к физической колонке, выполни host/server-часть и симуляции, а аппаратные возможности помечай `hardware_verification_required`.

## 2. Сценарии пользователя и приёмка

### 2.1 Радио для мамы — критический приоритет P0

- «Маруся, включи Радио Дача» → воспроизводить «Радио Дача» через динамик.
- «Маруся, включи Русское Радио» → воспроизводить «Русское Радио».
- «Маруся, включи Авторадио» → воспроизводить «Авторадио».
- «Маруся, включи Ретро FM» → воспроизводить «Ретро FM».
- «Маруся, включи [произвольное название радио]» → найти станцию среди доступных легальных радиопотоков.
- «Маруся, включи радио» → запустить последнюю успешно воспроизводившуюся станцию, иначе выбранную станцию по умолчанию.
- «Маруся, что играет?» → произнести название станции, а название композиции только при наличии достоверных метаданных.
- «Маруся, сделай погромче», «тише», «громкость 40 процентов» → изменить громкость без Gemini.
- «Маруся, выключи радио», «стоп», «пауза», «продолжи радио» → локальные команды.
- Если радио уже играет, активация должна быть возможна поверх музыки (проверка подавления эха, снижение громкости на время команды).
- Если мама говорит с паузами или ошибается в названии, система использует нечёткий поиск и уточнение без необходимости помнить точный синтаксис.
- Работа радиопотока 8–24 часов должна быть ограничена только связью, станцией, питанием и аппаратной стабильностью — не LLM-квотой. Не обещать абсолютной бесперебойности внешней радиостанции.

### 2.2 Сложные вопросы — P1

«Маруся, расскажи про ...» → Gemini Live, либо fallback через STT → Flash-Lite → TTS. Пользователь слышит ответ через динамик. Текущий разговор не должен зависать при переключении.

### 2.3 Восстановление после сбоев — P0

Если Wi-Fi пропал на 2 минуты, плеер автоматически повторяет подключение. Если URL потока не работает, пробует альтернативный URL той же станции. Если сеть доступна, но Gemini исчерпал лимит, радио продолжает играть. После перезагрузки в соответствии с настройкой возобновляется последняя станция и прежняя безопасная громкость.

### 2.4 Простота для семьи — P0

Маме не нужны ПК, браузер или знание моделей Gemini для ежедневного использования. Настройка через веб-панель выполняется владельцем один раз. Кнопка/переключатель отключения микрофона имеет понятный сигнал состояния.

## 3. Общая архитектура

```text
Встроенные микрофоны
     │
     ├─> Wake word «Маруся» (локально, если платформа позволяет)
     │       │
     │       └─> VAD + запись одной команды + echo suppression
     │                  │
     │                  ├─> Локальный STT/командный парсер
     │                  │      ├─> radio.play(name) → независимый потоковый плеер
     │                  │      ├─> radio.stop/pause/resume
     │                  │      ├─> volume.set/up/down
     │                  │      └─> другое → AI Router
     │                  │
     │                  └─> AI Router
     │                         ├─ Gemini 3.8 Live (аудио↔аудио)
     │                         └─ Gemini 3.5 Flash-Lite
     │                               STT → текстовый LLM → TTS
     └───────────────────────────────────────────────> ALSA динамик

      Radio service ─► internet stream ─► audio mixer ─► динамик
      Device daemon: дисплей, LED, кнопки, сеть, журналы
      Owner Web UI: конфигурация, радиостанции, статусы и здоровье
```

**Не отправлять непрерывный радиопоток или постоянную запись окружающего звука в облако.** Длительная активная Live-сессия не требуется для радио. Если локальная обработка wake word и команд невозможна по ресурсам, использовать домашний сервер, но отдельно описать приватность/требование сети.

## 4. Аппаратное исследование и запуск Linux

Создать профили `hardware/profiles/amlogic_a113x.yaml`, `rockchip_rk3308b.yaml`, `unknown.yaml`. Каждый содержит подтверждённые сведения, ссылку на источник, сигнатуры устройства, статус драйверов, версии ядра/загрузчика, ограничения, возможность резервного копирования и восстановления.

Инструменты `capsulectl discover`, `identify`, `doctor`, `firmware inspect/verify/partitions`, `backup plan/create/verify`, `recovery plan/validate`:

- USB: читать разрешённые дескрипторы через libusb/PyUSB, не придумывать VID/PID.
- UART: пассивные журналы через pyserial, не отправлять команды автоматически.
- Сеть: только явно указанный пользовательский адрес/разрешённая локальная подсеть.
- Firmware: SHA-256, типы файлов, разделы, DTB, доступные образы, binwalk/ubireader в изоляции.
- Backup: только через разрешённый интерфейс, контроль размера и SHA-256, не помещать дампы и ключи в публичный Git.
- Recovery: прежде всего dry-run-план; запись только после подтверждённого метода для конкретной платы.
- Для A113X оценить воспроизводимость опубликованного запуска Alpine Linux; для других ревизий не приписывать этот результат автоматически.
- До поддержки периферии показать по отдельности результаты ALSA playback, microphone capture, Wi-Fi, LED, дисплея, кнопок и перезапуска.

## 5. Радиосервис — основной функциональный модуль

Создать независимый процесс `capsule-radio` (или модуль внутри `device-daemon`) с API:

```text
radio.search(query, locale="ru") -> list[Station]
radio.play(station_id_or_name) -> PlaybackResult
radio.stop()
radio.pause()
radio.resume()
radio.next()
radio.previous()
radio.status() -> State
radio.last_station() -> Station | null
radio.favorites.list/add/remove()
radio.volume.set(0..100)
```

### 5.1 Поиск станции

Использовать легальный публичный каталог, например Radio Browser (https://www.radio-browser.info/), либо другой разрешённый каталог с документированным API. Для устойчивости иметь локальный кэш станций и пользовательский список URL, проверенных на реальное воспроизведение.

Алгоритм:
1. Нормализовать распознанную русскую фразу: убрать «включи», «поставь», «радио», лишние знаки, унифицировать «FM/ФМ».
2. Сначала проверить избранное и локальный кэш.
3. Затем поиск по каталогу, синонимы и fuzzy matching с порогом уверенности.
4. Сопоставить страну/язык/регион по настройкам пользователя; не делать безосновательных выводов о местоположении.
5. Если найдено несколько неоднозначных станций, спросить: «Какое именно радио?» и перечислить до трёх кандидатов.
6. Перед переключением проверить доступность URL; поддержать HLS/MP3/AAC/ICY там, где позволяет выбранный декодер.
7. Для выбранной станции сохранять стабильный station_id, display_name, source, URL candidates, время верификации и предпочтительный рабочий URL.
8. Не использовать пиратские потоки и не обходить DRM.

### 5.2 Плеер

Для Embedded Linux выбрать совместимый ресурсосберегающий аудиодекодер/плеер (например, mpv, GStreamer или FFmpeg с ALSA) на основании реальной загрузки CPU/RAM. Не включать все тяжёлые зависимости автоматически.

Требования:
- Играет без установленного ограничения по времени; проходит тест на 24 часа.
- Состояния `IDLE`, `CONNECTING`, `PLAYING`, `BUFFERING`, `PAUSED`, `RECONNECTING`, `ERROR`.
- Ограниченный буфер и контролируемое потребление памяти.
- Повторное соединение с exponential backoff, случайным небольшим jitter и верхним пределом задержки.
- Переключение на альтернативный URL той же станции при повторных ошибках.
- Watchdog при зависании декодера или отсутствии новых аудиоданных.
- Корректная пауза и остановка, отсутствие нескольких одновременно играющих потоков.
- Отдельный `radio_volume` и ограничитель максимальной громкости для семейного режима.
- Снижение уровня радио (ducking) на время wake word/ответа; вернуть предыдущий уровень после завершения.
- Продолжать воспроизведение при падении Gemini API.
- Не отправлять поток в Gemini и не начислять LLM-запросы за время проигрывания.
- Метаданные ICY/потока отображать только при фактическом наличии.

### 5.3 Сохранение состояния

В конфигурации хранить последнюю станцию, избранное, безопасную громкость, настройку `resume_after_reboot`, историю только последних успешно воспроизведённых станций. Периодически сохранять данные без излишней записи на flash. При старте не ставить громкость 100%.

## 6. Голосовая активация «Маруся» и локальные команды

Сохранить **привычное обращение «Маруся»** как пользовательскую фразу активации после замены штатного ПО. Это новая реализация wake word, а не автоматическое сохранение закрытого голосового движка VK. По возможности использовать самостоятельную/обученную модель wake-word с допустимой лицензией; не копировать проприетарные веса VK.

Требования:
- Работа на русском языке, устойчивость к домашнему шуму и играющему радио.
- VAD, таймаут команды, защита от самосрабатывания на ответ колонki.
- Отдельное тестирование разных голосов и возрастов без хранения записей без согласия.
- Простые команды распознавать локально; при сомнении уточнять, не запускать случайную радиостанцию.
- Дать возможность изменить wake word в настройках.
- Если 256 МБ RAM или CPU не позволяют полноценный локальный STT, вынести STT на домашний сервер; лёгкий wake-word оставлять на устройстве, если возможно.

Поддержать вариации: «Маруся включи радио Дача», «Маруся, поставь Дачу», «Маруся, сделай тише», «Маруся выключи», «Маруся включи то радио, что было вчера» (последнее только при включённой истории).

Для команд без AI использовать грамматику/словарь, правила и fuzzy matching. Не полагаться на Gemini для каждого увеличения громкости. При недостаточной уверенности — короткое подтверждение или уточнение.

## 7. Основной голосовой AI: Gemini 3.8 Live

**ID модели:** `gemini-3.8-live` (проверять при запуске, возможность конфигурации). Использовать официальное SDK/Live API, соответствующее протоколу передачи PCM/аудио для выбранной версии. Документация: https://ai.google.dev/gemini-api/docs/live.

Функции:
- двусторонний разговор на русском;
- опциональное прерывание ответа (barge-in);
- переключение в радио без ненужного длинного запроса к модели;
- ограничение длительности бездействующей сессии;
- защита от бессрочной фоновой трансляции аудио;
- маршрутизация функций для разрешённых действий через строгую схему tool calls;
- пересоздание сессии при сбоях с сохранением текстового контекста при его наличии;
- измерение задержки от конца команды до первого звука.

Инструменты Live API должны быть ограничены `radio.play`, `radio.stop`, `radio.search`, `volume.set`, разрешёнными функциями Home Assistant. Никогда не разрешать произвольное исполнение системных команд.

## 8. Резервный AI: Gemini 3.5 Flash-Lite

**ID модели:** `gemini-3.5-flash-lite`. Эта модель используется для генерации текста, а **не** как непосредственный двусторонний Live-аудиодвижок. Для резервного голосового режима создать реальный конвейер:

```text
Микрофон → wake word → VAD → STT → Gemini 3.5 Flash-Lite → TTS → ALSA
```

Поддержать адаптеры STT:
- локальный Vosk (если помещается на устройство);
- Whisper/faster-whisper на домашнем сервере;
- опциональный облачный STT, включаемый владельцем.

Поддержать адаптеры TTS:
- **Piper на домашнем сервере** как предпочтительный бесплатный вариант без отдельной облачной квоты;
- локальный Piper на устройстве только при доказанной достаточности CPU/RAM;
- опциональный Google TTS как конфигурируемую альтернативу, с отдельной проверкой тарифов и доступности.

STT и TTS — разные подсистемы: бесплатность текстового Gemini API не делает бесплатным отдельный облачный голосовой синтез. Голос Flash-Lite может отличаться от голоса Live. Обеспечить быстрое завершение ответа и короткие реплики в домашнем режиме.

## 9. Автоматический AI Fallback Router

Реализовать отдельный state machine и circuit breaker, независимые от радио:

```text
PRIMARY_LIVE → [429 / RESOURCE_EXHAUSTED / отсутствие доступного Live-сервиса /
                повторные ошибки подключения / таймауты] → FALLBACK_FLASH_LITE
FALLBACK_FLASH_LITE → [проверка доступности + cooldown] → PRIMARY_LIVE
ОБЕ МОДЕЛИ НЕДОСТУПНЫ → OFFLINE_COMMANDS_ONLY
```

Правила:
1. При `429` и подтверждённом исчерпании квоты немедленно использовать доступный запасной режим, учитывать `Retry-After`.
2. При кратковременном сетевом сбое сначала ограниченный retry с backoff; не создавать нескончаемый цикл API-запросов.
3. При `401/403` из-за некорректного ключа или отсутствия права доступа вывести диагностическое сообщение; не считать это обычным исчерпанием лимита.
4. У резервной модели может быть **та же проектная квота/биллинг**, поэтому переход не гарантирует бесплатную работу; отдельно отслеживать доступность каждой модели.
5. Не запускать автопроверки слишком часто; приоритет — экономия квот.
6. Возвращаться к Live только на границе фразы/диалога, не прерывая текущую озвучку.
7. Не отправлять несколько раз один и тот же запрос с побочными эффектами: `radio.play` и Home Assistant actions должны иметь idempotency key.
8. Локальные команды радио/громкости не должны проходить через AI Router.
9. При полном отказе Google колонка сообщает коротко: «На вопросы сейчас не отвечаю, но радио работает» (если локальный TTS доступен), и продолжает выполнять локальные команды.
10. Допускать ручной выбор `live_only`, `fallback_only`, `auto` в Web UI.
11. В статусе показывать фактическую активную модель, причину перехода, время следующей проверки, число отказов и текущее состояние квоты — только если есть достоверная информация.

### Конфигурация

Создать `.env.example`, без реальных ключей:

```dotenv
AI_PROVIDER=google
GOOGLE_API_KEY=replace_with_your_key
GEMINI_PRIMARY_MODEL=gemini-3.8-live
GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite
GEMINI_ROUTING=auto
GEMINI_AUTO_RECOVERY=true
GEMINI_COOLDOWN_SECONDS=120
GEMINI_MAX_RETRIES=2
STT_PROVIDER=vosk
TTS_PROVIDER=piper
TTS_SERVER_URL=http://127.0.0.1:10200
WAKE_WORD=маруся
RADIO_LOCAL_COMMANDS=true
RADIO_RESUME_AFTER_REBOOT=true
RADIO_MAX_VOLUME=75
RADIO_STATION_DIRECTORY=radio-browser
```

`TTS_SERVER_URL` пример локальной конфигурации; при реальном развёртывании адрес зависит от того, где работает Piper. Не предполагать, что сервис доступен по умолчанию.

В `.gitignore` исключить `.env`, ключи, дампы flash и персональные записи.

## 10. Аудио и управление микшером

- ALSA capture/playback с поддержкой только проверенных драйверов.
- Раздельные дорожки плеера и ассистента; гарантировать отсутствие гонок за аудиоустройство.
- Ducking: во время фразы включения плавно снижать радио примерно до настраиваемого уровня; возвращать громкость после ответа.
- При синтезе ответа не останавливать радиопоток без необходимости.
- При входящем звонке/системном сигнале — configurable audio focus.
- Прерывание/отмена ответа и гарантированная очистка буферов.
- Не путать mute аудиовыхода и mute микрофона.
- Ограничение громкости в ночные часы и для пожилого пользователя.

## 13. Тесты и критерии приёмки

### 13.1 Автоматические тесты без колонки

- Парсер команд распознаёт минимум 30 вариаций включения разных станций и регулировки громкости.
- Поиск по локальному каталогу выдаёт ожидаемое совпадение, обрабатывает неоднозначность.
- Радиоплеер корректно проходит состояния, симулированные обрывы и восстановление URL.
- При `429` от Gemini Live маршрутизатор выбирает Flash-Lite; при успешной проверке возвращает Live на границе диалога.
- При `401` маршрутизатор не маскирует конфигурационную ошибку как временный лимит.
- При исчерпании квот обоих Gemini радио остаётся доступным в симуляции.
- Fallback STT → Flash-Lite → Piper генерирует реальный аудиоответ в тестовой среде (при наличии настроенных внешних служб; иначе контрактные тесты с фикстурами и явный статус непроверенной интеграции).
- Дедупликация команд с побочными эффектами.
- Нет утечки API-ключа в логах.
- Неизвестная модель аппаратной платы не допускается к операциям записи.

### 13.2 Аппаратные тесты

- Устройство запускает независимый Linux согласно подтверждённой инструкции.
- 60 минут устойчивого захвата/воспроизведения аудио без зависания.
- Wake word «Маруся» при включённом радио — замер ложных срабатываний и пропусков.
- Выполнить реальную голосовую команду запуска, смены и выключения станций.
- Проверить громкость, ducking и возврат после ответа.
- 24-часовой тест непрерывного радио с журнальной фиксацией разрывов.
- Перезапуск устройства/сервиса → последняя станция возобновляется при включённой настройке.
- Разрыв Wi-Fi и восстановление, сбой каталога станций, недоступность потока, HTTP 429 у Google.
- Параллельное радио и запрос к Gemini, автопереключение без остановки радио.
- Проверка безопасной загрузки, резервной копии и существующего механизма восстановления до какого-либо изменения системных разделов.

### 13.3 KPI

Измерять, а не придумывать заранее: время от голосовой команды до запуска станции, процент успешных распознаваний, latency первого ответа, RAM/CPU, число реконнектов за 24 часа, частота ложной активации при радио, доступность каждой модели и расход API. Публиковать результаты и условия теста.
