# Подключение настоящей Капсулы

**В этом репозитории нет подтверждённого универсального способа установки независимой ОС.** Сначала установите точную ревизию и рабочий путь восстановления. Ниже описаны опубликованные API; физического устройства в тестовой среде не было.

## Gemini-for-Capsula — Linux-агент, верхнее кольцо и передний дисплей

[yawaflua/Gemini-for-Capsula](https://github.com/yawaflua/Gemini-for-Capsula), изучен commit `5f2057329adb3a8455859960b7c015717a1cf886`:

- Go-агент для Linux, ALSA, VAD, кнопки, LED-кольцо и 7-сегментный дисплей;
- `internal/display/seg7/seg7.go` описывает A113X и kernel `line-display`; это не универсальная карта GPIO;
- панель с паролем, командой `light.night` и подтверждением агента;
- собственный WS-протокол и Gemini-сессия. Наш Python WS API с ним не взаимозаменяем;
- один из режимов wake word отправляет фоновый микрофон на домашний сервер. Это отдельная настройка проекта; изучите её до включения. В нашем приложении такая отправка не включается.

Если совместимый агент уже работает на вашей Linux-системе, настройте пароль панели и ID своей колонки. Заменять ОС заранее необязательно: при существующем SSH/root можно сначала оценить временный `try-agent` из Makefile upstream; его условия описаны в [простом руководстве](simple-assistant-setup.md). В нашем `.env`:

```dotenv
GEMINI_CAPSULA_URL=http://127.0.0.1:8090
GEMINI_CAPSULA_DEVICE_ID=ваш-device-id
GEMINI_CAPSULA_PANEL_PASSWORD=собственный_пароль_панели
```

`8090` — пример свободного порта другого сервера, не значение upstream по умолчанию: не запускайте два сервера на одном 8080. Для сервера в другой сети используйте HTTPS/защищённый туннель.

Перезапустите наше приложение → «Свет» → «Проверить серверы колонки». Настройте верхнюю зону, выберите **Постоянный** свет → «Отправить верхний свет на колонку». Адаптер авторизуется в панели, находит подключённую сессию именно заданного device ID, проверяет capability `light.night`, отправляет разрешённую команду. Яркость 0 выключает ночник, поскольку upstream трактует 0 как яркость по умолчанию. Успех означает ответ агента, а не оптическое наблюдение LED.

Анимации «дыхание/пульс» нашего превью через этот API не отправляются. Передние RGB-цвета в превью — виртуальный сценарий: настоящий сегментный дисплей не объявляется RGB. Не запускайте два конкурирующих драйвера экрана (`mordy` и агент). Не копируйте драйверы SPI/DTB на другую ревизию без проверки.

## marusya-server — настройки переднего дисплея

[v3rt3p/marusya-server](https://github.com/v3rt3p/marusya-server): исследованы `src/main.ts`, `src/config.ts`, `src/storage/types.ts`. API содержит `GET /devices`, `PATCH /devices/:id`, поля `clockEnabled`, `clockBrightness` и revision. Подтверждения доставки дисплею этот API не возвращает.

Для **собственного уже настроенного сервера**:

```dotenv
MARUSYA_SERVER_URL=http://127.0.0.1:31105
MARUSYA_DEVICE_ID=ваш-id
```

«Свет» → «Проверить серверы колонки» → настроить яркость/включение передней зоны → «Применить яркость переднего дисплея». Адаптер читает актуальную конфигурацию, сохраняет остальные поля, увеличивает general revision и отправляет PATCH. Он не передаёт цвет и эффект на физический передний дисплей. Upstream не имеет compare-and-swap: избегайте одновременного редактирования из нескольких панелей.

В изученной версии API не содержит обязательной аутентификации; держите его на localhost или за защищённым прокси. Не используйте встроенные примерные сторонние STT/TTS URL без своей настройки. Перенаправление штатной колонки на этот backend и работа её загрузчика в нашем проекте не проверены.

## Остальные источники

[inmyuse.github.io/marusia](https://inmyuse.github.io/marusia/) / [репозиторий](https://github.com/inmyuse/marusia) — React/3D-витрина. Модель и код не скопированы: нестандартная non-commercial лицензия; это не аппаратный драйвер.

[LibreCapsula](https://t.me/librecapsula) — публично доступна карточка группы; переписка/прошивки в рамках этой проверки недоступны. Сообщения участникам не отправлялись. Никаких технических свойств по названию группы не предполагаем.

[Debian live, A113X](research/source-register.md) — опубликованное исследование Linux на одной платформе. Не руководство для RK3308B и не аппаратная верификация нашего экземпляра.
