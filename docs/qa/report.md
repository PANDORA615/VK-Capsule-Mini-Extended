# Проверка версии 0.2.1

Цель текущей версии: подключение ИИ и управление колонкой без фотографий, скриншотов, модели корпуса и отдельного радиовиджета. Радио сохранено как команда ассистента.

Среда: Debian 13 / x86_64, Python 3.12.14, Chromium, mpv 0.40.0. Физическая колонка, ключи Google и реальные голосовые модели не подключены.

Машиночитаемые результаты: [pytest.xml](pytest.xml), [browser-results.json](browser-results.json), [версии среды](test-environment.json). Проверки браузера не сохраняют изображения.

```bash
pip install -e '.[dev,ai]'
# Для теста настоящего декодера установить mpv в ОС.
pytest -q
ruff check capsule tests scripts
ruff format --check capsule tests scripts
mypy capsule
# С запущенным capsulectl serve:
CHROMIUM_PATH=/usr/bin/chromium python scripts/check_ui.py
```

В тестовой среде есть два предупреждения зависимостей: переименование pytest CallSpec2 в anyio и deprecation старого httpx TestClient в Starlette. Это не падения.

Непроверено на реальном устройстве: SSH/root, загрузчик, ALSA, микрофоны, Wi-Fi, дисплей, LED, Bluetooth, AEC, акустическая активация, реальные сутки потока и производительность в 256 МБ. Нет подтверждённого универсального установщика root/ОС. `capsulectl ssh` использует уже существующий доступ и не создаёт его.

Настоящие вызовы Google и качество Vosk/Piper требуют ключа и моделей владельца. Веб-кнопка остановки прекращает ожидание/озвучку, но не гарантирует отмену уже начавшегося биллинга API. Громкость браузерного ответа, радиопроцесса и ALSA аппаратного агента — отдельные выходы.
